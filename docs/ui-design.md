# BGP Packet Analyzer - 画面設計仕様書

## 1. 概要

### 1.1 ドキュメントの目的
本書はBGP Packet Analyzerの画面設計仕様を定義する。各画面のレイアウト、コンポーネント、インタラクション、状態遷移を詳細に記述する。

### 1.2 対象読者
- フロントエンド開発者
- UIデザイナー
- QAエンジニア

### 1.3 関連ドキュメント
- design.md（要件・技術設計）
- design-duckdb-wasm.md（DuckDB WASM 移行時の当初提案。実装との差分は同文書の冒頭を参照）
- todo.md（修正済み課題の記録）

## 3. 共通コンポーネント

### 3.1 ヘッダー

```
┌─────────────────────────────────────────────────────────────────┐
│ 🦈 BGPShark  [Dashboard][Messages][Neighbors][Routes][SQL]      │
│              📁 file.pcap  [+ New File]  [☀ Light]  [GitHub ↗]  │
└─────────────────────────────────────────────────────────────────┘
```

| 要素 | 説明 |
|------|------|
| ロゴ | アプリ名、クリックでメッセージエクスプローラーへ（未読込時は `/`）。アプリ名は sm 未満では非表示 |
| ナビゲーション | 各画面へのリンク（ファイル未読込時は非表示）。幅が足りないときは横スクロール |
| ファイル名 | 読み込み中のファイル名（md 未満の画面幅では非表示） |
| New File | 状態をリセットしてアップロード画面へ戻る |
| テーマ切替 | Light → Dark → Auto（システム設定に追従）を巡回。選択は localStorage に保存 |
| GitHub | リポジトリへのリンク |

**状態**
- ファイル未読込: ナビゲーション・New File ボタンとも非表示（テーマ切替と GitHub は常時表示）
- ファイル読込済: 全リンク表示

### 3.2 フィルタバー

メッセージエクスプローラーのフィルタUI（`useFilter` + `QueryInput`）。
経路分析画面は Prefix 検索（4.5節）を使い、このフィルタバーは持たない。

```
┌─────────────────────────────────────────────────────────────────┐
│ Filter: [Simple][Advanced]   Show: [BGP Only][All Packets]      │
│                                              [Clear Filter]     │
│ Query: [type = NOTIFICATION and src_ip = 10.0.0.1            ]  │
│                                                                 │
│ Showing 3 of 1,234 packets                                      │
└─────────────────────────────────────────────────────────────────┘
```

| 要素 | 説明 |
|------|------|
| Simple / Advanced | ルールビルダー（フィールド・演算子・値のドロップダウンを AND で連結）と自由入力の切り替え |
| フィルタ入力（Advanced） | フィルタ式を入力。候補をオートコンプリート表示（↑↓ で選択、Enter で確定） |
| BGP Only / All Packets | BGP以外のIPパケットも一覧に含めるかの切り替え |
| Clear Filter | フィルタをリセット（入力かルールがあるときだけ表示） |
| ステータス行 | 「Showing N of M packets」、フィルタ実行中は "filtering..." |

適用は入力に追従（Apply ボタンはない）。構文エラーは入力が 600ms 止まってから
表示するので、打鍵の途中で赤くならない。
フィルタ式は URL の `?filter=` に載る。

**フィルタ構文例**
```
type = OPEN
type = NOTIFICATION and src_ip = 10.0.0.1
src_ip = 10.0.0.1 or dst_ip = 10.0.0.1
asn = 65001
prefix = 10.0.0.0/8
community = 65000:100
capability contains "Route Refresh"
not (type = KEEPALIVE)
```

利用可能なフィールドは `src/lib/filter/parser.ts` の `FILTER_FIELDS` を参照
（`type` / `src_ip` / `dst_ip` / `router_id` / `src_as` / `asn` / `origin` /
`next_hop` / `prefix` / `withdrawn` / `community` / `capability`）。
`src` `dst` `as` `aspath` `nexthop` `nlri` `router-id` `my_as` `large-community`
は別名として受け付ける。

**バリデーション**
- 構文エラー時: 入力欄を赤枠表示、エラーメッセージをステータス行に表示（入力停止から600ms後）
- 結果0件時: 一覧エリアに空表示、ステータス行が「Showing 0 of N packets」

### 3.3 通知

汎用のトーストシステムは持たない。知らせる内容ごとに置き場所が決まっている。

| 種類 | 表示場所 | 挙動 |
|------|----------|------|
| パーサ警告 | ヘッダ直下の警告バナー（`WarningBanner`） | 1行に畳んで表示。クリックで全件展開。キャプチャに属するので画面をまたいで残る |
| ドロップ失敗 | 画面下中央のトースト | 拡張子・サイズ違反など。[×] で閉じる |
| 読み込み失敗 | アップロード画面のエラー表示 | メッセージと [Try Again] |
| SQLエラー | 結果パネル内 | DuckDB のメッセージをそのまま表示（4.6節） |

```
┌─────────────────────────────────────────────────────────────────┐
│ ⚠ 3 parse warnings                                    [Show ▼]  │  ← ヘッダ直下
└─────────────────────────────────────────────────────────────────┘

                  ┌────────────────────────────┐
                  │ Invalid file type. ... [×] │  ← ドロップ失敗（画面下中央）
                  └────────────────────────────┘
```

### 3.4 ローディング表示

進捗率は出さない。読み込みは「何をしているか」の一行とスピナーで表す。

| フェーズ | 表示 |
|----------|------|
| ファイル読み込み・パース | ドロップゾーン内にスピナー ＋ "Parsing file..."（サンプルは "Loading sample..."） |
| キャプチャ復元（リロード・ディープリンク） | 画面中央にスピナー ＋ "Restoring capture…" |
| 画面の遅延読み込み | 画面中央にスピナー |
| フィルタ実行中 | ステータス行に "filtering..." |

#### 4.1.3 コンポーネント仕様

**ドロップゾーン**

| プロパティ | 値 |
|------------|-----|
| サイズ | 最大幅 `max-w-xl`（レスポンシブ、高さは内容なり） |
| ボーダー | 2px dashed（`border-hair-strong`） |
| ホバー時 | ボーダー・背景ともアクセント色（`border-accent` / `bg-surface-sunken`） |
| ドラッグオーバー | ボーダー `border-accent`、背景 `bg-accent-subtle` |

色は付録Aのトークン（CSS カスタムプロパティ）を参照。ライト／ダークで値が変わるため、
本書では固定のカラーコードではなくトークン名で示す。

なお、ドラッグ＆ドロップはこのドロップゾーンに限らずアプリ全体で受け付ける
（`useFileDropzone`。ドラッグ中は画面全体にオーバーレイを表示）。

**ファイルバリデーション**

上限値と対応拡張子は `src/lib/file-constraints.ts` が唯一の定義元。
UI の文言もそこから生成するため、本書と実装がずれた場合は実装が正となる。

| チェック項目 | エラーメッセージ |
|--------------|------------------|
| 拡張子が .pcap / .pcapng / .cap でない | "Invalid file type. Please upload a .pcap, .pcapng, .cap file." |
| ファイルサイズ > 10MB | "File too large. Maximum size is 10MB (got N.NMB)" |
| マジックナンバー不正 | "Invalid pcap file: unrecognized magic number" / "Invalid pcapng byte order magic" |
| IPパケットなし | "No IP packets found in the pcap file." |

BGPメッセージが1件もないキャプチャはエラーにしない（IPパケットとしては読めているので、
All Packets 表示で中身を確かめられる）。

**サンプルファイルリンク**
- クリックで `/sample.pcapng` を自動読み込み（実体は pcapng 形式）
- 初めてのユーザー向けデモ用

```
┌─────────┐  ファイル選択   ┌──────────┐  パース完了   ┌───────────┐

└─────────┘                └──────────┘               └───────────┘
```

| 状態 | 表示 |

#### 4.2.3 コンポーネント仕様

**サマリーカード**

6枚。総パケット数と、メッセージタイプ別の件数。

| カード | 内容 | クリック動作 |
|--------|------|--------------|
| Packets | 総パケット数 | フィルタなしでメッセージ一覧へ |
| OPEN / UPDATE / NOTIFICATION / KEEPALIVE / ROUTE REFRESH | タイプ別メッセージ数 | `type=<TYPE>` でフィルタしてメッセージ一覧へ |

**アラートリスト**

自動検出するアラート条件（`computeAlerts` in `src/pages/DashboardPage.tsx`）:

| 重要度 | 条件 | 表示 |
|--------|------|------|
| 🔴 Critical | NOTIFICATION 1件につき1件 | エラーコード名／サブコード名と送受信IP |
| 🟡 Warning | 同一ピアペアで OPEN が4件以上（セッションフラップ） | OPEN数と推定確立回数 |
| 🟡 Warning | 10秒以内に10 Prefix以上の Withdrawn | 撤回Prefix数と時間窓 |

重要度の高い順、同じ重要度なら新しい順に並ぶ。各行から該当パケットへ移動できる。

**ネイバーテーブル**

| カラム | 説明 |
|--------|------|
| Neighbor Pair | 送受信IPペア（双方向を1行に集約） |
| Pkts | 総パケット数 |
| OPEN / UPD / NOTIF | メッセージタイプ別カウント |
| Status | アラート有無のステータス |

- 行クリック → Neighbor分析ページで該当Routerの詳細表示
- テーブル右上に「View All Neighbors →」リンク

**タイムライン**

| 仕様 | 値 |
|------|-----|
| X軸 | 時間（キャプチャ開始からの相対時間）。キャプチャ全体を等間隔のバケットに分割 |
| Y軸 | バケットあたりのUPDATE数（最大値で正規化） |
| 表示 | UPDATE（棒）、NOTIFICATION（上部の赤マーカー） |
| インタラクション | 棒・マーカーのホバーで件数と時刻をツールチップ表示。マーカーのクリックで該当パケットをメッセージ一覧で開く |

**Prefix検索**

| 入力形式 | 例 | 動作 |
|----------|-----|------|
| CIDR表記 | 10.0.0.0/8 | Match の方向に従って照合 |

#### 4.6.3 コンポーネント仕様

**SQLエディタ**

プレーンな `textarea`。シンタックスハイライト・補完・行番号はない。

| 機能 | 説明 |
|------|------|
| 実行 | `Ctrl+Enter` / `Cmd+Enter`、または [▶ Run] |
| Clear | 入力を空にする |
| 実行時間 | 成功時にエディタ下へ「Execution: Nms」 |
| エラー表示 | 結果パネルに DuckDB のメッセージを表示。0件と混同しないよう、失敗したクエリは履歴に積まない |

**スキーマビューア**

サイドバーの「📁 Schema」パネル。テーブル名クリックで代表カラムを展開する。
一覧しているのは `packets` / `messages` / `as_path` / `nlri` / `withdrawn` /
`communities`。ここに出ていない `capabilities` / `path_attributes` /
`large_communities` にもクエリはできる。全カラムは `src/lib/db/schema.ts` を参照。

**クエリテンプレート**

| テンプレート名 | クエリ概要 |
|----------------|------------|
| Neighbor Summary | ピア別パケット集計 |
| AS_PATH Stats | AS番号出現頻度 |
| Prefix Flapping | Flap回数の多いPrefix |
| Error Analysis | エラーコード別集計 |
| Message Types | メッセージタイプ別件数 |

クリックでエディタの内容を置き換える。初期表示は Neighbor Summary。

**クエリ履歴**

成功したクエリを新しい順に最大10件保持（重複は繰り上げ）。クリックでエディタに戻す。
保存はしないので、リロードで消える。

**結果テーブル**

| 機能 | 説明 |
|------|------|
| 表示件数 | 先頭100行のみ描画。超えた分は「Showing first 100 of N rows」と表示 |
| Export | 結果全件をCSVでダウンロード（`query-result.csv`） |

ソートやセル選択のUIはない（並べ替えは `ORDER BY` で書く）。

**実行制限**

タイムアウト・行数上限・DDL/DML の禁止はいずれも設けていない。DuckDB はブラウザ内の
使い捨てインスタンスで、テーブルは読み込んだキャプチャから毎回作り直されるため、
書き換えても壊れるのは手元のセッションだけ。重いクエリはタブが固まる形で現れる。

## 5. レスポンシブデザイン

### 5.1 ブレークポイント

| 名前 | 幅 | 対応デバイス |
|------|-----|--------------|
| sm | < 640px | スマートフォン |
| md | 640-1024px | タブレット |
| lg | > 1024px | デスクトップ |

### 5.2 画面別対応

境界は `lg`（1024px）。ここを下回ると2ペインが成立しないので、
Messages / Neighbors / Routes は「一覧 → 選択で詳細に切り替え、[← Back] で一覧」という
スマホアプリ的なマスター/ディテールに変わる（`useIsCompact`）。
モーダルやタブは使わない。ブレークポイントをまたいでリサイズしても、
選択状態に応じた側が表示される。

**メッセージエクスプローラー / Neighbor分析 / 経路分析**
- lg以上: 2ペイン（一覧 ＋ 詳細）。境界はドラッグでリサイズ可能
- lg未満: 一覧と詳細を切り替え表示（ペイン境界は非表示）

**ダッシュボード**
- lg以上: サマリーカード6列
- sm〜lg: 3列 / sm未満: 2列。他のパネルは常に縦積み

**SQLコンソール**
- lg以上: エディタ＋結果の左に対して、テンプレート／履歴／スキーマを右サイドバーに配置
- lg未満: サイドバーがエディタの下へ回る

## 7. エラーハンドリング

### 7.1 エラー種別と表示

| エラー種別 | 表示方法 | 復帰方法 |
|------------|----------|----------|
| ファイル形式エラー | ドロップゾーン下の赤いメッセージ／画面下のトースト | 別ファイル選択 |
| パースエラー（一部） | ヘッダ直下の警告バナー + 継続 | 読めた分はそのまま解析 |
| DuckDB初期化失敗 | SQLコンソールに「DuckDB not initialized」 | フィルタはインメモリ評価に自動フォールバック。他画面は影響なし |
| SQLエラー | 結果パネルにDuckDBのメッセージ | クエリ修正 |
| 描画時の例外 | エラーバウンダリの画面（リセット可能） | リセットしてアップロード画面へ |
| ネットワークエラー | 該当なし（サンプル取得を除きオフライン動作） | - |

### 7.2 エラーメッセージ

ユーザーフレンドリーなメッセージを表示:

```
✗ Bad: "PCAP_MAGIC_MISMATCH: 0xd4c3b2a1 expected, got 0x00000000"
✓ Good: "This doesn't look like a valid pcap file. Please check the file format."
```

## 付録A: カラートークン

色はライト／ダークで値が変わるため、コンポーネントは生の16進値ではなく
セマンティックなトークン名で参照する。定義元は `src/index.css`（CSSカスタム
プロパティ）、Tailwind 側の名前は `tailwind.config.js`。

| 用途 | トークン | Tailwind 名の例 |
|------|----------|-----------------|
| 背景（最背面） | `--canvas` | `bg-canvas` |
| 面 / 沈んだ面 / 浮いた面 | `--surface`, `--surface-sunken`, `--surface-raised` | `bg-surface` |
| 罫線 | `--hair`, `--hair-strong` | `border-hair` |
| テキスト（強→弱） | `--text-strong`, `--text-body`, `--text-muted`, `--text-dim` | `text-muted` |
| アクセント | `--accent`, `--accent-hover`, `--accent-fg`, `--accent-subtle` | `bg-accent` |
| 重要度 | `--critical`, `--warning`, `--ok`（+ `-subtle`） | `text-critical` |
| BGPメッセージ種別 | `--msg-open`, `--msg-update`, `--msg-notification`, `--msg-keepalive`, `--msg-route-refresh` | `text-bgp-open` |

ライトが既定。OSがダークを要求すればダークに切り替わり、`<html>` の
`data-theme` があればそれが優先される。本文中で🔴🟡🟢と書いている箇所は
重要度トークンに対応する。

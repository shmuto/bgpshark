# BGP Packet Analyzer - 画面設計仕様書

## 1. 概要

### 1.1 ドキュメントの目的
本書はBGP Packet Analyzerの画面設計仕様を定義する。各画面のレイアウト、コンポーネント、インタラクション、状態遷移を詳細に記述する。

### 1.2 対象読者
- フロントエンド開発者
- UIデザイナー
- QAエンジニア

### 1.3 関連ドキュメント
- design.md（要件・技術設計）
- design-duckdb-wasm.md（DuckDB WASM設計）

## 2. 画面一覧と遷移

### 2.1 画面一覧

| # | 画面名 | パス | 状態 | 説明 |
|---|--------|------|------|------|
| 1 | ファイルアップロード | `/` | 実装済 | 初期画面、PCAPファイル読み込み |
| 2 | メッセージエクスプローラー | `/messages` | 実装済 | BGPメッセージ一覧と詳細。読み込み完了後の着地画面 |

## 3. 共通コンポーネント

### 3.1 ヘッダー

```
┌─────────────────────────────────────────────────────────────────┐
│ 🦈 BGP Packet Analyzer  [Messages][Neighbors][Routes][SQL]      │
│                       📁 file.pcap  [+ New File]  [GitHub ↗]    │
└─────────────────────────────────────────────────────────────────┘
```

| 要素 | 説明 |
|------|------|
| ロゴ | アプリ名、クリックでメッセージエクスプローラーへ（未読込時は `/`） |
| ナビゲーション | 各画面へのリンク（ファイル未読込時は非表示） |
| ファイル名 | 読み込み中のファイル名（md 未満の画面幅では非表示） |
| New File | 状態をリセットしてアップロード画面へ戻る |
| GitHub | リポジトリへのリンク |

**状態**
- ファイル未読込: ナビゲーション・New File ボタンとも非表示
- ファイル読込済: 全リンク表示

### 3.2 フィルタバー

メッセージエクスプローラー、経路分析画面で使用する共通フィルタUI。

```
┌─────────────────────────────────────────────────────────────────┐
│ 🔍 [type = NOTIFICATION and src_ip = 10.0.0.1          ] [Apply]│
│    ────────────────────────────────────────────────────         │
│    Quick: [OPEN] [UPDATE] [NOTIFICATION] [KEEPALIVE]  [Clear]   │
└─────────────────────────────────────────────────────────────────┘
```

| 要素 | 説明 |
|------|------|
| フィルタ入力 | フィルタ式を入力（構文ハイライト付き） |
| Apply | フィルタ適用（Enter でも実行） |
| Quick フィルタ | ワンクリックでメッセージタイプ絞り込み |
| Clear | フィルタをリセット |

**フィルタ構文例**
```
type = OPEN
type = NOTIFICATION and src_ip = 10.0.0.1
src_ip = 10.0.0.1 or dst_ip = 10.0.0.1
asn = 65001
prefix = 10.0.0.0/8
community = 65000:100
capability contains "Route Refresh"
not (type = KEEPALIVE)
```

利用可能なフィールドは `src/lib/filter/parser.ts` の `FILTER_FIELDS` を参照
（`type` / `src_ip` / `dst_ip` / `router_id` / `src_as` / `asn` / `origin` /
`next_hop` / `prefix` / `withdrawn` / `community` / `capability`）。
`src` `dst` `as` `aspath` `nexthop` `nlri` は別名として受け付ける。

**バリデーション**
- 構文エラー時: 入力欄を赤枠表示、エラーメッセージをツールチップで表示
- 結果0件時: 「No matching packets」を一覧エリアに表示

### 3.3 通知トースト

処理完了やエラー時に右下に表示。

```
┌────────────────────────────┐
│ ✓ Loaded 1,234 packets     │  ← 成功（緑）
│                    [×]     │
└────────────────────────────┘

┌────────────────────────────┐
│ ⚠ Parse warning: 3 packets │  ← 警告（黄）
│   skipped                  │
│                    [×]     │
└────────────────────────────┘

┌────────────────────────────┐

```

| タイプ | 表示時間 | 色 |
|--------|----------|-----|
| 成功 | 3秒後自動消去 | 緑 (#10B981) |
| 警告 | 5秒後自動消去 | 黄 (#F59E0B) |
| エラー | 手動で閉じるまで表示 | 赤 (#EF4444) |

| チェック項目 | エラーメッセージ |
|--------------|------------------|
| 拡張子が .pcap / .pcapng / .cap でない | "Invalid file type. Please upload a .pcap, .pcapng, .cap file." |

#### 4.3.3 コンポーネント仕様

**Neighbors Overview テーブル**

キャプチャ内で観測された全Routerを一覧表示。

| カラム | 説明 |
|--------|------|
| Router ID / IP | BGP Router ID（OPEN受信時）またはIPアドレス |
| AS | AS番号（OPENから取得、不明時は「-」） |
| Msgs | 送受信メッセージ総数 |
| State | アラート有無（NOTIFICATION有→Alert） |
| Last Activity | 最後のメッセージ時刻 |

**Router識別ロジック**:
1. OPENメッセージのBGP Identifierを優先
2. OPENがない場合はIPアドレスで識別
3. 同一Router IDで複数IPがある場合は集約

行クリック → 下部に詳細パネル表示

**Neighbor Detail パネル**

選択したRouterの詳細情報を表示。

**Message Summary**
- メッセージタイプ別の送受信カウント
- 円グラフまたは棒グラフでの可視化オプション

**Sessions with this Router**
- 選択Routerと通信している相手Routerの一覧
- 各セッションのメッセージ数とステータス
- 行クリックでSession Timeline表示

**Alerts from this Router**
- 選択Routerが送受信したNOTIFICATIONを時系列表示
- [View →] クリックでメッセージエクスプローラーへ遷移

**Session Timeline**

選択したピアペア間のメッセージを時系列表示。

| カラム | 説明 |
|--------|------|
| Time | タイムスタンプ |
| Direction | → (送信) / ← (受信) |
| Type | メッセージタイプ |
| Summary | 簡易情報 |

色分け:
- OPEN: 緑背景
- UPDATE: 通常
- KEEPALIVE: グレー
- NOTIFICATION: 赤背景

**Capability Diff（実装済、`CapabilityDiff` コンポーネント）**

ピアペア間のOPENメッセージを並べて比較（`src/components/neighbor/CapabilityDiff.tsx`）。

| 表示項目 | 説明 |
|----------|------|
| Session Fields | BGP Version, My AS, Hold Time, BGP Identifier。Hold Time不一致はエラー扱いしない（最小値がネゴシエートされるため）。Router ID衝突（双方が同一値）とAS不整合はエラー表示 |
| Capability Mismatches | 片方のみサポートのCapabilityを先頭に表示。Multiprotocol/ADD-PATHはAFI/SAFI単位で比較（コード単位ではない） |
| Matching Capabilities | 双方サポート済みのCapability（折りたたみ表示） |
| 三値の状態表示 | advertised by both / only local / only remote を色だけでなくアイコン＋テキストで表現 |

トラブルシューティングに有用:
- Capabilityミスマッチの検出（AFI/SAFI粒度）
- Hold Time不一致の確認（エラーではない旨を明示）
- Router ID衝突・AS不整合の検出
- 片側のOPENしか取得できていない場合も一方比較として表示継続

**Prefix Activity**

選択セッションでのPrefix増減サマリー。

| 指標 | 説明 |
|------|------|
| Announced | UPDATEでアナウンスされたPrefix数 |
| Withdrawn | Withdrawされたprefix数 |
| Net Change | 差分 |
| Current Prefixes | 最終的なPrefix数（推定） |
